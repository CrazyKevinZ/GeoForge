# GeoForge 数据转换器 - 使用说明

**GeoForge GIS数据转换器** 是一款专业的 **多格式 GIS/CAD 数据互转工具**。
支持在 **10 种输出格式** 之间互转：GeoJSON / JSON / CSV / (OV)TXT / KML / OVKML / GPX / DXF / OSM / XML，
转换过程带实时进度、已用时间与剩余时间估算，转换完成后弹窗给出完整输出路径。

专注满足 **kistom.com 在线地图预览** 与 **外业软件（奥维互动地图、JOSM 谷歌地球等）** 的坐标正确可用。

---

## 1. 功能概述

- **源文件格式（10 种）**：`DXF` `DWG` `GeoJSON` `JSON` `CSV` `TXT` `KML` `GPX` `OSM` `XML`
  - CAD 图纸：`DXF`（完整支持）；`DWG`（需先转成 DXF，见 §5）。
  - 已移除早期版本中的 `SVG`。
- **目标格式（10 种）**：
  `GeoJSON` / `JSON` / `CSV` / `(OV)TXT` / `KML` / `OVKML` / `GPX` / `DXF` / `OSM` / `XML`
- **任意互转**：以上任意格式作为输入，可转换为任意目标格式（如 GeoJSON→KML、KML→DXF、DXF→(OV)TXT 等）。
- **参考经纬度 / CGCS2000 3° 带**：源为投影制坐标（DXF/DWG）时，输入参考点的经纬度并按
  **CGCS2000 高斯-克吕格 3° 带** 换算为 WGS84；内置 Z29/Z30/Z35–Z40 一键预置中央经线，见 §6。
- **输出大小估算**：选择源文件与目标格式后可手动点「开始估算」查看输出文件大小。
- **实时进度**：进度条百分比 + 已用时间 + 估算剩余时间；转换中可「取消转换」。
- **输出文件提示**：转换完成后弹窗列出所有输出文件的完整路径。
- **文件夹操作**：可自行修改输出目录，并提供「打开输出目录」一键定位。

## 2. 运行方式

### 2.1 直接运行编译版（推荐）
本体在：
```
\GeoForge.exe
```
双击 `GeoForge.exe` 即可运行，无需安装 Python 或任何依赖。

### 2.2 从源码运行（开发）
```bash
cd "\Source code\dxf2geojson_app"
pip install ezdxf pyinstaller
python main.py
```

### 2.3 关于 `GeoForge_ui.json`
程序运行时会在 exe 同目录**自动生成**一个 `GeoForge_ui.json` 界面状态配置文件，内容如：
```
// GeoForge 界面状态配置文件
// 作用：记录主窗口的位置与大小（geometry），下次启动时恢复上次的窗口状态。
// 删除：可以安全删除。删除后程序会使用默认窗口大小，并在下次关闭窗口时自动重新生成本文件。
{"geometry": "986x580+457+208"}
```
- **作用**：记住主窗口的位置与大小，下次启动时恢复，无需关心。
- **删除**：可安全删除；删除后程序用默认窗口大小，关闭时自动重建。
- **备注**：本文件由程序自动生成与更新，删除不会影响任何功能。

## 3. 使用步骤

1. **选择源文件**：点击「选择文件」选择任意支持格式的文件，或将文件直接拖拽到窗口。
2. **输入参考经纬度（仅 DXF/DWG → 其余格式时必填）**：
   填 CGCS2000 3° 带内任一点的经纬度（格式：`经度,纬度`，如 `87.000000, 40.000000`），
   或点下方 Z29/Z30/Z35–Z40 按钮一键填入对应带中央经线，见 §6。目标为 DXF 时可不填。
3. **选择目标格式**：点击右侧 10 个格式徽章按钮之一（两排各 5 个）选择输出格式；
   点击下方「开始估算」和「开始转换」查看输出大小和转换操作（即格式卡副标题所述）。
4. **设置输出目录**：默认为桌面，可点「浏览…」修改，也可点「打开输出目录」直接定位结果。
5. **查看估算大小**：界面显示「估算输出大小：≈ xxx」，可点「开始估算」手动刷新。
6. **开始转换**：点击「开始转换」，底部实时显示百分比 / 已用时间 / 剩余时间。
7. **查看结果**：完成弹窗列出所有输出文件完整路径；打开输出目录即可找到文件。

## 4. 目标格式说明

| 按钮    | 实际输出文件                     | 说明                                                       | 适用            |
|---------|--------------------------------|------------------------------------------------------------|-----------------|
| GeoJSON | `竣工图.geojson`                | 标准 GeoJSON；线/面带编号名称，带文字的点 `label:true`       | kistom / 地图    |
| JSON    | `竣工图.json`                   | 通用 JSON（标准 GeoJSON 结构），内容同上                    | kistom           |
| CSV     | `竣工图.csv`                    | 逗号分隔表格；空行分隔要素，线/面带编号，文字点带 text         | kistom / 表格    |
| (OV)TXT | `竣工图KS.txt` + `竣工图OV.txt`  | 一个按钮生成两个文件（见下）                                | kistom + 奥维    |
| KML     | `竣工图.kml`                    | 标准 KML；线/面带编号名称，文字点 `<name>` 为实际文字         | Google Earth / 奥维 |
| OVKML   | `竣工图.ovkml`                  | 专为奥维优化的 KML（WGS84 `lon,lat,0`），不与普通 KML 重名   | 奥维（连通线）    |
| GPX     | `竣工图.gpx`                    | 全球定位交换格式，点/线带名称与编号                           | 奥维 / GPS 软件  |
| DXF     | `竣工图.dxf`                    | 原样复制源 DXF（坐标不变，不编号）                           | CAD/GIS          |
| OSM     | `竣工图.osm`                    | OpenStreetMap XML；节点/路径带 `version` 元数据，兼容 JOSM  | JOSM / kistom    |
| XML     | `竣工图.xml`                    | 通用 XML（KML 兼容结构）                                   | kistom           |

### 4.1 (OV)TXT 组合输出
选择 **(OV)TXT** 时一次生成两个文件：
- `竣工图KS.txt`：kistom 兼容文本表（表头 + 编号线名 + 文字），供 kistom 在线预览。
- `竣工图OV.txt`：奥维互动地图标签格式（每行 `名称 经度 纬度`，单空格分隔）。
  > 注：奥维 TXT 只能导入点/标签，无法由 TXT 生成连通线；如需奥维连通线请用 **OVKML**。

### 4.2 线编号
GeoJSON / JSON / CSV / TXT / KML / OVKML / XML / GPX / OSM 的**每条线/面均带编号名称**
（如 `ROAD #1`、`ROAD #2`），便于在地图与外部软件中区分。DXF 因保持源文件原样而不编号。

## 5. 关于 DWG 文件

DWG 为 Autodesk 专有二进制格式，**本软件不直接解析 DWG**（纯 Python 开源库仅能读取 DXF）。
DWG 转换功能入口保留，但需外部工具先行转换：

- 推荐：在 CAD 软件（AutoCAD / 中望 / 浩辰 / CAXA 等）中将 DWG **另存为 DXF** 后再导入本软件。
- 程序读取 DWG 时如检测不到外部转换器（ODA File Converter，现为收费软件），会提示：
  请先在 CAD 中另存为 DXF，或用免费方式转成 DXF 后使用；这不影响 DXF 的正常使用。

## 6. 参考经纬度 / CGCS2000 3° 带换算（DXF/DWG → 其余格式）

- DXF 中的坐标是 **CGCS2000 高斯-克吕格投影米制**（x=东向、y=北向），并非经纬度。
- 在「参考经纬度」处填入 3° 带内**任意一点**的经纬度（`经度,纬度`），程序据此反算并
  将全部坐标换算为 WGS84 经纬度，保证 kistom / 奥维 / Google Earth 中位置正确。
- **一键预置**：下方 Z 按钮对应 CGCS2000 3° 带的中央经线，点击自动填入对应带预设坐标：
  Z29→87°、Z30→90°、Z35→105°、Z36→108°、Z37→111°、Z38→114°、Z39→117°、Z40→120°（纬度默认 40.0）。
  每个按钮不同底色，便于快速识别。
- 若目标格式为 DXF（仍是米制），则无需参考经纬度。

## 7. kistom 在线预览与外部软件

- **kistom 预览**：GeoJSON / JSON / CSV / TXT(KS) / KML / OVKML / XML / GPX / OSM 均可在
  kistom（`http://kistom.com/my/map.php`）加载；其中文字点正确显示、线/面正确断线并带名称。
- **奥维互动地图**：用 **OVKML** 获得连通线/面与名称；用 **OVTXT（OV.txt）** 导入点/文字标签。
- **JOSM**：OSM 输出已带 `version` 等元数据，可直接在 JOSM 打开。
- **Google Earth**：使用 KML 即可。

## 8. 源码结构

```
Source code/
├── UI.MD / UI.png / LOGO.png     # 界面与品牌参考
└── dxf2geojson_app/
    ├── main.py                   # 程序入口
    ├── gui.py                    # tkinter 图形界面（格式按钮/进度/参考经纬度/输出目录）
    ├── build.py                  # PyInstaller 一键编译脚本
    └── core/
        ├── reader.py             # DXF/DWG 读取（ezdxf），DWG 需外部转换
        ├── readgeo.py            # GeoJSON/JSON/CSV/TXT/KML/GPX/OSM/XML 读取
        ├── exporter.py           # 10 种格式导出（含 (OV)TXT、OVKML）
        ├── proj.py               # CGCS2000 高斯-克吕格 → WGS84 换算
        ├── estimator.py          # 输出大小估算
        ├── converter.py          # 转换编排 + 进度回调 + 双文件输出
        └── model.py              # 统一中间数据模型
```

## 10. 注意事项

- 转换采用**内存解析**模型，超大图纸（数十万实体）建议先看「估算大小」确认规模。
- **DXF→经纬度格式**必须填参考经纬度并按 CGCS2000 3° 带换算，否则坐标位置会错。
- kistom 的文字渲染需要文字的 `label` 标记；线/面名称用于在图层管理器中区分各要素。
- (OV)TXT 的 KS/OV 两份文件分别面向 kistom 与奥维；OVTXT 无法表达连通线，连通线请用 OVKML。
